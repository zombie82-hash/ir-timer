# 설치 보고서 생성기 v0.2.1 — 배포 안내

현장 메모를 정형 설치 보고서로 바꾸고, 그 작성 시간을 측정하는 **정적 웹앱(PWA)** 입니다.
빌드 도구·번들러·npm 의존성·서버가 없습니다. 파일을 그대로 올리면 끝입니다.

측정 목표: **아이폰 현장에서 실제로 열리고, 5건 측정을 시작할 수 있게** (기능 추가 없음, 배포 형태만 변경)

---

## 1. 파일 구조

```
index.html               A 조건 — 설치 보고서 생성기 (v0.2 그대로 + PWA 설정)
stopwatch.html           B 조건 — 종이 양식 작성 시간 스톱워치
manifest.json            PWA 매니페스트 (standalone, 아이콘, 테마 색)
sw.js                    Service Worker (앱 셸 캐시 / 오프라인)
icons/
  icon-192.png           홈 화면 아이콘 (192, any maskable)
  icon-512.png           홈 화면 아이콘 (512, any maskable)
README.md                이 문서
```

`index.html`, `manifest.json`, `sw.js`, `icons/` 는 **같은 폴더에** 있어야 합니다.
`stopwatch.html` 도 같은 폴더에 둡니다. 폴더 구조를 바꾸지 마세요.

---

## 2. 배포 — GitHub Pages (단계별)

1. **저장소 만들기**
   github.com 로그인 → 오른쪽 위 `+` → **New repository**
   - Repository name: 예) `ir-timer` (아무 이름이나 가능)
   - **Public** 선택 (Private는 무료 플랜에서 Pages가 안 됩니다)
   - `Add a README file` 는 체크하지 않아도 됩니다 → **Create repository**

2. **파일 업로드**
   저장소 화면 → **Add file** → **Upload files** →
   이 폴더의 `index.html`, `stopwatch.html`, `manifest.json`, `sw.js`, `README.md` 를 끌어다 놓고,
   `icons` 폴더째로 `icons/icon-192.png`, `icons/icon-512.png` 도 함께 올립니다.
   → 아래 **Commit changes** 클릭.
   - 웹 업로드로 폴더를 올리려면 드래그할 때 **폴더 자체**를 끌어다 놓으면 경로가 유지됩니다.
   - 업로드 후 저장소 최상단에 `index.html` 이 보여야 합니다(`하위폴더/index.html` 이면 안 됨).

3. **Pages 켜기**
   저장소 → **Settings** → 왼쪽 **Pages**
   - **Source**: `Deploy from a branch`
   - **Branch**: `main` / 폴더 `/ (root)` → **Save**
   - 1~2분 뒤 새로고침하면 위쪽에 주소가 나옵니다.

4. **주소 확인**
   `https://<계정명>.github.io/<저장소명>/`
   → 열어서 **"설치 보고서 생성기"** 화면이 뜨면 성공. (`stopwatch.html` 은 `.../stopwatch.html`)
   - 주소는 반드시 `https://` 여야 합니다. `file://` 로 열면 카메라·클립보드·Service Worker 가 모두 막힙니다.

> 사내 규정상 GitHub를 쓸 수 없으면, 같은 파일을 **아무 https 정적 호스팅**(Netlify Drop, Cloudflare Pages 등)에
> 그대로 올려도 됩니다. 조건은 하나 — **https + 폴더 구조 유지**.

## 3. 아이폰에서 열기 / 홈 화면에 추가

1. 아이폰 **사파리**에서 배포 주소를 엽니다. (카톡 인앱 브라우저 말고 사파리)
2. 하단 **공유 버튼**(□↑) → 아래로 스크롤 → **홈 화면에 추가** → **추가**
3. 홈 화면 아이콘으로 열면 주소창 없는 **전체 화면(standalone)** 으로 뜹니다.
   - `stopwatch.html` 도 같은 방법으로 따로 홈 화면에 추가해 두면 편합니다.

### 처음 한 번은 온라인으로 열어야 합니다

앱 셸(HTML·아이콘)은 **첫 실행 때** 내려받아 캐시에 저장됩니다.
그래서 **최초 1회는 와이파이/LTE 가 되는 곳에서** 열어 두어야 하고, 그 뒤부터는 비행기 모드에서도 열립니다.
현장에 들어가기 전에 한 번 열어 두는 것을 권합니다. (화면 상단에도 같은 안내가 있습니다)

## 4. 측정 순서

| 조건 | 파일 | 방법 |
|---|---|---|
| **A** (앱) | `index.html` | 현장 메모 입력 → **[보고서 생성]** → AI 초안 검토·수정 → **[완료]** |
| **B** (종이) | `stopwatch.html` | 종이 양식 작성을 시작할 때 **[시작]**, 끝나면 **[정지]** |

- A 조건의 T1(메모 입력) / T2(구조화) / T3(검토·수정)는 자동 계측됩니다.
  실패한 호출은 기록되지 않고, 메모를 다시 입력하면 T1부터 새로 잽니다.
- B 조건은 **총 소요 시간만** 기록합니다(회차·소요(초)·메모 한 줄). 5건 측정이 끝나면 이 파일은 버려도 됩니다.
- 기록은 각 파일 화면 아래 **[JSON 내보내기]** 로 파일로 받습니다.
  - A: `ir_records_YYYYMMDDHHmm.json` (배열)
  - B: `b_records_YYYYMMDDHHmm.json` (배열, `mode: "B"`)
  - 두 파일 모두 배열이라 나중에 합쳐서 비교할 수 있습니다.

### 기록이 저장되는 곳 (중요)

기록은 서버가 아니라 **브라우저 localStorage** 에 저장됩니다.
- 그래서 **주소(도메인)가 바뀌면 기록은 이어지지 않습니다.** `file://` 로 쓰던 v0.2 기록은 새 https 주소에서 보이지 않습니다 — 의도된 동작이고, 마이그레이션은 없습니다.
- 같은 주소라도 **사파리 일반 탭**과 **홈 화면 앱**은 저장 공간이 다를 수 있습니다. 측정은 한쪽으로 통일해서 하세요.
- 시크릿 모드에서는 저장되지 않습니다. 아이폰 설정에서 "웹사이트 데이터 차단"이 켜져 있으면 저장이 막힙니다.

## 5. API 키 설정 (A 조건, 최초 1회)

1. `index.html` 실행 → 맨 위 **[키 설정]** (또는 본문의 `LLM 설정 (Gemini API 키)`)
2. Google AI Studio에서 발급한 Gemini API 키를 붙여넣기 → 입력칸 밖을 누르면 저장됩니다.
3. 상태 표시가 **"API 키 설정됨"** 으로 바뀌면 준비 완료.

- 키는 그 브라우저의 localStorage(`geminiApiKey`)에만 저장되고, 요청 헤더(`x-goog-api-key`)로만 전송됩니다. 화면에 다시 출력하지 않습니다.
- 모델은 `gemini-3.8-flash` 고정입니다(파일 상단 `MODEL` 상수 한 줄).
- 키를 지우려면 같은 패널의 **[저장된 키 삭제]**.

## 6. PDF·공유 동작 (v0.2.1 정정 사항)

- **[인쇄 / PDF 저장]** → `window.print()` 로 **인쇄 대화상자**를 엽니다.
  아이폰에서는 인쇄 미리보기에서 **공유**하거나 **파일에 저장**할 수 있습니다. → **인쇄 → 공유 → 카톡** 순서.
- **[텍스트 공유]** → `navigator.share` 로 **텍스트 요약만** 공유합니다(현장명·일자·작업자·작업 내용).
  공유 시트에서 받는 사람(카톡 대화)을 고릅니다. 공유 시트가 없으면 **클립보드 복사**로 자동 폴백합니다.
- PDF 라이브러리는 넣지 않았습니다. 브라우저만으로 Blob PDF를 만드는 경로는 이번 범위가 아닙니다.

## 7. 업데이트할 때 (버전 올리기)

파일을 고쳐서 다시 올릴 때는 **`sw.js` 맨 위 `VERSION` 을 반드시 올리세요.**

```js
const VERSION = 'v0.2.1-1';   // → 'v0.2.1-2'
```

- `install` 에서 새 셸을 프리캐시하고, `activate` 에서 옛 캐시(`ir-shell-*`)를 지웁니다.
- `skipWaiting()` + `clients.claim()` 이라 앱을 완전히 닫았다 열 필요 없이 다음 실행에 새 버전이 적용됩니다.
- 그래도 옛 화면이 보이면: 홈 화면 앱을 삭제 후 다시 추가(가장 확실) 또는 사파리에서 새로고침 2회.
- `VERSION` 을 안 올리면 **캐시 우선** 정책 때문에 예전 파일이 계속 나옵니다.

## 8. 이번 버전에서 확인한 것 / 확인하지 못한 것

**확인함 (PC Chrome 156, `python3 -m http.server` 로컬 서버 = localhost는 https와 같은 보안 컨텍스트)**
- Service Worker 등록·활성화(activated), `clients.claim` 으로 페이지 제어, 셸 6개 항목 프리캐시
- **오프라인 재접속**: 개발자도구 Offline 상태에서 `index.html` / `stopwatch.html` **모두 열림**(새로고침 + 새 탭 콜드 로드 둘 다)
- **갱신 경로**: `sw.js` VERSION 을 v0.2.1-1 → v0.2.1-2 로 올리면 새 SW가 활성화되고 옛 `ir-shell-*` 캐시가 삭제, 새 HTML 반영
- `manifest.json` 파싱·필수 필드(display=standalone, start_url=./, icons 192/512 any maskable), 아이콘 192·512 실제 디코드
- A 조건: 모의 200 응답으로 생성 → T2 표시 → 인쇄(window.print 호출) → T3 → [완료] → localStorage `irRecords` 1건(mode A, t1+t2+t3=total, printed=true) → JSON 내보내기 파일명
- 텍스트 공유: 공유 시트가 없는 환경에서 클립보드 폴백 동작(현장명 포함 텍스트)
- B 스톱워치: 시작→정지 기록, 회차/소요(초)/메모, `bRecords` 2건, 새로고침 후 유지, JSON 내보내기
- 좁은 화면(390px)에서 기록 표 8열이 한 화면에 들어옴, 콘솔 오류·pageerror 0건
- `index.html` 에서 B 조건 코드(`bBtn`/`bStart`/`mode:"B"`) 잔존 없음

자동 점검 **67개 항목 전부 PASS** (Playwright + 시스템 Chrome, 로컬 서버).

**확인 못 함 (실기기 없음 → 미검증, 그대로 남겨 둡니다)**
- **아이폰 사파리에서의 실제 동작 전체** — 홈 화면 추가, standalone 전체 화면, 상태 표시줄/세이프에어리어
- **iOS 오프라인 실행** — iOS는 캐시를 축출할 수 있어 오래 두면 안 열릴 수 있음
- iOS 인쇄 미리보기 → 공유 → 카톡 전달, iOS 공유 시트 문구/동작
- 사파리 일반 탭과 홈 화면 앱의 localStorage 공유 여부
- 유효한 Gemini 키로 실제 200 응답(생성 품질·지연) — 키가 없어 여전히 NOT TESTED

배포 직후 아이폰에서 **한 번 열어 키 입력 → 생성 1회 → 완료 → 홈 화면 추가 → 비행기 모드로 열기**까지
